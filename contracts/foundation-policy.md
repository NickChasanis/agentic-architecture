# Foundation policy — 1.0 implementation baseline

The owner authorized implementation of all five steps without further approval pauses on 2026-09-12. This delegates remaining bounded pilot implementation choices, not public deployment, billing, or removal of acceptance obligations. This baseline covers ID-01–06 and HTTP-01 only; catalog remains draft.

- Local HTTPS merchant/API origin: https://localhost:3443. Issuer: https://localhost:8443/realms/agentic-pilot. Bind published ports to 127.0.0.1. Backend runs on host; both browser and backend see the same issuer. No forwarded-header trust, credentialed CORS, arbitrary return URLs, or HTTP identity injection.
- Login transaction: 256-bit random browser-binding cookie, state, nonce and PKCE S256 verifier; five-minute absolute lifetime. Store only the binding hash, plus state/nonce/verifier, server-side. Starting another login in the same browser supersedes the previous transaction. Atomically delete-and-return matching unexpired transaction before token exchange. Invalid/missing binding or state fails without creating a session. Token exchange failure consumes the transaction; retry starts a new login.
- Bound transactions to 1,000 live rows using serialized creation, clean expired rows on creation, and reject saturation with IDENTITY_SERVICE_UNAVAILABLE. Limit login starts to 20 per minute per remote address in this single local process; bounded limiter map. Provider discovery/token calls time out after five seconds. Connectivity/timeouts map to IDENTITY_SERVICE_UNAVAILABLE; invalid protocol/token responses to LOGIN_FAILED; invalid callback shape/transaction to LOGIN_RESPONSE_INVALID; absent/disabled principal to ACCOUNT_UNAVAILABLE.
- Application session: opaque 256-bit identifier, hash stored in PostgreSQL, 30-minute idle/8-hour absolute expiry. Secure, HttpOnly, SameSite=Lax, Path=/, host-only __Host-pilot-session cookie. Rotate on login, revoke previous application session. Recheck active principal on every protected request. No provider tokens stored after login and no refresh-token behavior.
- Mutations: require exact configured Origin and session-bound X-CSRF-Token after session authentication; denied requests cannot mutate domain data. Logout revokes session and clears cookie; provider SSO remains separate.
- Identity key is verified issuer/subject, never username/email. Local active owner/staff membership and shop grants control access. Owners create/list all shops in their tenant; staff list only granted shops. Active ungranted staff get an empty shop list; inaccessible tenant gives generic 404. Current checks beginning after committed revocation deny; already-authorized requests may complete.
- Keep existing closed input/output schemas, error envelopes, name trimming, UUID/slug validation, 16 KiB mutation limit and no-store. Tenant and shop lists are ID-ascending and bounded by synthetic fixture size, not production pagination. Create-shop slug is globally unique and immutable; conflicts disclose no ownership.
- Shops owns shop records and trusted tenant context. Identity owns principals, memberships, grants, transactions and sessions. Identity permission checks consume trusted shop IDs/tenant IDs and do not import Shops persistence. Composition root connects modules; consumers import only wire contracts.
- Transaction cookie is __Host-pilot-login: Secure, HttpOnly, SameSite=Lax, Path=/, host-only, Max-Age=300. Clear it on every callback, successful or failed. Malformed callback/unknown state removes the transaction associated with that browser binding (not other browsers); no binding cannot select or consume any transaction. Starting again deletes the previous binding's transaction. Cleanup also removes expired rows.
- CSRF tokens are independent 256-bit random values stored server-side with their session, returned only by authenticated no-store introspection, compared with constant-time comparison after equal-length validation. Every new session has a new token; logout/expiry removes its validity. Do not log tokens.
- Login revokes only the previous application session presented by that browser cookie, not other device/browser sessions. Separate browsers may remain signed in concurrently.
- Error precedence: parser/size/media errors may precede authentication; session then CSRF then resource authorization precedes state-specific errors. Database availability failures map to SERVICE_UNAVAILABLE on session/discovery/shop routes; auth-start/callback storage failures map to IDENTITY_SERVICE_UNAVAILABLE. Unknown internal exceptions map to INTERNAL_ERROR. No database/transport/provider messages are reflected.
- Foundation wire baseline is the unchanged ID-01–06 plus HTTP-01 definitions in operations/http.json and wire.schema.json at d7b322f, composed with this policy 1.0; the other commerce operations remain unimplemented/draft. Acceptance tests must enforce policy beyond schema shape.
- Callback storage outage clears the browser cookie and creates no session but may prevent server-side deletion. Such rows expire after five minutes and cannot resume without the old secret binding; once storage recovers cleanup removes them. Report IDENTITY_SERVICE_UNAVAILABLE, never assert cleanup succeeded during an outage. Integration-owned foreign keys enforce grant/shop tenant consistency after both module migrations.
- This local run uses existing tool access, deterministic tests and one independent read-only reviewer. No separately billed model API. Reviewer checkpoint budget: 15 minutes per pass with concrete findings; renew locally only within the authorized task. Numeric budgets for a later comparative multi-worker benchmark remain unaccepted.
